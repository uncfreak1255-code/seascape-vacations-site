# Page Conversion Rate Optimization

Identify what prevents the visitor from taking the page's intended action and
return changes supported by the page and traffic evidence. Distinguish measured
results from conversion hypotheses.

## Scope and constraints

Use the active brief, page source, and available traffic context to establish
the audience, conversion goal, and problem. Ask only for missing context that
changes the recommendation. A form-friction request needs the affected fields,
validation, errors, and completion path, not a full page audit.

Assess relevant weaknesses in value proposition, headline/message match, CTA
placement and hierarchy, scannability, proof, objection handling, and friction.
Let observed impact determine priority; these are lenses, not a fixed sequence.

- Copy changes follow the active brief and `docs/process/content-quality-gate.md`.
- Meaningful visual changes use `seascape-design-specialist`, `DESIGN.md`, and
  `docs/process/design-review-workflow.md`.
- Owner claims use `owner-proof-integrity`; property claims use canonical facts.
- Experiment proposals and activation follow `docs/process/learning-contract.md`
  and repository approval rules. A recommendation does not authorize launch.
- Use [page patterns](references/page-patterns.md) for page-type-specific guidance;
  use [experiment ideas](references/experiments.md) only when forming test hypotheses.
  Examples are options, not requirements to add claims, remove navigation, or
  change the design system.

## Completion

For an audit, return prioritized findings with evidence, concrete edits, and
hypotheses worth testing. Give 2–3 headline or CTA alternatives when wording is
the issue. Include the smallest useful verification or measurement plan.

For authorized implementation, continue through the required content and
rendered checks and fix in-scope failures before handoff. State what was
verified and what conversion effect remains unmeasured.
