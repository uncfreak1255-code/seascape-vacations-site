# Seascape CRO experiment ideas

Use only the examples that address an observed guest or owner decision. Each is
a hypothesis, not a requirement or a predicted lift. Fix a demonstrated broken
control directly; an experiment is for an uncertain product choice.

## Guest decisions

| Decision | Possible comparison | Evidence needed |
|---|---|---|
| Choose a suitable home | Order of verified capacity, bedrooms, amenities, and location details on property cards | Observed selection friction; property truth |
| Choose dates | Placement or wording of the existing availability action | Current booking path and its supported events |
| Continue from a guide | Contextual link to relevant existing stays versus current CTA | Guide intent, target fit, internal-link requirements |
| Understand a property | Order of factual details and objections near the booking action | Repeated guest questions or observed hesitation; canonical facts |
| Continue booking | Clearer handoff wording before the existing booking destination | Destination behavior and drop-off evidence, if available |

## Owner decisions

| Decision | Possible comparison | Evidence needed |
|---|---|---|
| Understand the service | Placement of existing service/process explanation | Owner inquiry or observed confusion |
| Assess credibility | Placement of approved proof near the inquiry action | Current owner proof assets; no invented outcomes or counts |
| Complete an inquiry | Field order or required/optional balance | Receiving handler contract and actual follow-up needs |
| Recover from an error | Error wording or help placement | Reproduced failure; retained values and accessible feedback |

For field and state checks, use [form checks](forms.md). For a visual comparison,
use the established design specialist, critic, and rendered review lane. Changes
to shared navigation or footer links also need the internal-link proof required
by `AGENTS.md`.

## Before proposing a live test

Name the observation, proposed change, primary event, guardrail event, eligible
audience, readback window, and decision rule. Check current analytics-owned
traffic evidence and whether the effect can be measured in that window. If it
cannot, return a bounded usability investigation or an untested hypothesis.

Use `docs/process/learning-contract.md` and existing approval rules for activation.
Preserve consent, property truth, owner proof, and booking/submission contracts.
An inconclusive comparison is not a winner. Report a measured conversion effect
only from the matching analytics evidence.
