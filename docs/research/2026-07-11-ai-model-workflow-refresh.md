# AI Model And Workflow Refresh - July 11, 2026

## Decision

Adopt new capabilities through bounded task-level pilots, not a repo-wide model
or plugin reset. Seascape already has the right workflow spine: five SEO roles,
an active brief, local design specialist and critic, DataForSEO access, content
gates, and rendered browser proof. The current gap is using those surfaces
together before source work starts.

## Last-Month Signals

- OpenAI launched the GPT-5.6 family on July 9 with stronger agentic coding,
  design, computer-use, and multi-agent workflows. Use Sol as a bounded
  challenger for high-value design or difficult review work; keep ordinary
  implementation on the current Codex lead unless a measured pilot shows a
  reason to change.
- OpenAI's plugin directory packages apps, skills, templates, and related tools.
  A plugin is a capability bundle, not authority. Install one only when a live
  task needs a callable surface and the repo's existing route cannot do the job.
- Bing Webmaster Tools expanded AI Performance on June 16 with Intents,
  Topics, Citation Share, and Compare. This is a promising measurement input,
  but its connector and durable receipts belong in `seascape-analytics`, not
  this site repo.
- Google clarified that `llms.txt` has no positive or negative effect on Google
  Search or AI-feature visibility. Keep the existing file accurate for broader
  machine readers, but do not treat it as a Google ranking project.
- GitHub's recent Copilot code-review write-up found that workflow and tool-use
  tuning mattered more than simply adding tools. That supports the current
  cleanup-first decision: repair the brief and review route before adding more
  agents.
- Figma's design-agent updates make custom context, tools, and skills useful for
  inspectable design handoffs. Figma remains optional until a real frame is the
  approved contract; screenshots and source stay authoritative in this repo.

## Use Now

1. Run proof and attack research in parallel for one query family.
2. Record keyword demand, inspected competitor URLs, information gain,
   design/format strategy, tools used, and request cost in the active brief.
3. Use the Seascape design specialist and critic for new guides or meaningful
   rescues; use a current design-capable model as one bounded challenger.
4. Keep real location and property photography factual. Use image generation
   only for moodboards, composition studies, or clearly non-evidentiary assets.
5. Verify every meaningful visual change with desktop/mobile screenshots,
   accessibility checks, and the repo's visual regression gate.

## Pilot Later

- Add Bing AI Performance to the analytics evidence stream after a clean
  ownership and credential review in `seascape-analytics`.
- Compare Sol, the regular Codex lead, and one external design challenger on
  the same approved page brief before changing any default routing.
- Use Figma when a guide-template system needs reusable visual specs across
  several routes, not as a mandatory detour for every content edit.

## Do Not Add

- no sixth SEO role
- no copied SEO or AEO pack
- no global model-default change
- no mandatory Figma dependency
- no generated factual location or property photography
- no site-repo AI visibility dashboard
- no plugin install without a named task, owner, and verification receipt
